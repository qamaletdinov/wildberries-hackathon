# Wildberries Shipment Forecasting

Time-series forecasting practice project based on a Wildberries hackathon:
predict shipment volume for 1,000 routes over the next eight 30-minute slots.

The public repository focuses on reproducible EDA, leakage-safe temporal
validation, heterogeneous gradient boosting, and a two-stream temporal
convolutional network. Competition data, trained weights, submissions, and
heavy generated artifacts are intentionally not published.

contamination. It must not be presented as the validated solution.

## Data contract

Expected local files:

```text
train_solo_track.parquet
test_solo_track.parquet
```

Train grain: one `route_id × timestamp` row on a regular 30-minute grid. Test
contains 1,000 routes and eight future timestamps per route. The dataset is not
redistributed; place authorized copies in the repository root. Parquet and CSV
files are ignored by Git.

## Verified EDA findings

All numbers below are generated by `eda_exam_rehearsal.py` from the local data:

- 4,630,000 train rows, 1,000 routes, and 4,630 timestamps per route;
- no missing route-time slots, duplicated keys, nulls, or negative targets;
- target is zero in 69,841 rows (`1.508%`); the longest zero run is 135 slots;
- train uses a regular 30-minute grid;
- test is exactly `1,000 routes × 8 horizons`;
- the final train day is partial: 22 of 48 daily slots;
- route-centered lead-lag analysis found the strongest tested status signal at
  `status_3(t) → target(t+1)`, correlation `0.393`;
- periodogram diagnostics show daily, half-daily, and weekly components;
- first-to-last chronological quarter mean ratio is `1.214`, so temporal drift
  must be considered.

Outliers and zeros are diagnosed but not silently removed.

## Leakage-safe evaluation

Every fold reproduces the deployment question:

```text
history available through 10:30
              ↓
forecast 11:00, 11:30, ..., 14:30 for every route
```

Safety properties covered by tests:

- future target/status changes cannot alter past-origin features;
- one route cannot contaminate another route's rolling features;
- feature/label order is `horizon × route`;
- validation origins match the test time of day;
- early stopping uses an inner chronological tail, never the outer fold.

The ensemble reports two estimates:

- `ensemble_oof_fit`: weights fitted and scored on the same OOF rows; useful but optimistic;
- `ensemble_crossfit`: each fold is scored using weights fitted on the other folds; preferred for comparison.

## Model architecture

```text
seasonal daily / weekly / robust median
                   │
LightGBM ─ XGBoost ─ categorical CatBoost ─ two-stream TCN
                   │
        identical temporal folds
                   │
        validation error correlation
                   │
       constrained cross-fitted blend
```

The TCN has separate causal dilated Conv1D branches for target history and six
operational status sequences. Their representations are fused with a route
embedding, per-channel scales, and future cyclic time features, producing all
eight horizons directly.

## Preliminary result

Comparable two-fold diagnostics over all 1,000 routes produced:

| Model | WAPE + absolute relative bias ↓ |
|---|---:|
| Cross-fitted ensemble | **0.3221** |
| LightGBM | 0.3269 |
| XGBoost | 0.3345 |
| Two-stream TCN | 0.3368 |
| CatBoost | 0.3653 |
| Seasonal median | 0.3979 |

The tree and cross-fitted ensemble values come from one combined run. The
two-stream TCN value comes from a controlled A/B run on the same folds and
training budget; the combined ensemble run still used the earlier single-stream
TCN and assigned it approximately zero weight. Therefore this table is a model
comparison, not a claim that the reported ensemble already incorporates the
two-stream network.

These are preliminary diagnostics, not final leaderboard claims. The two folds
are adjacent days, and the full four-fold run was intentionally stopped before
completion. Model rankings changed materially by day, which supports temporal
cross-validation and heterogeneous experts but also limits confidence in the
reported point estimate.

## Setup

Install the core EDA environment:

```bash
uv sync --frozen
```

Install all ensemble experts, including PyTorch:

```bash
uv sync --frozen --extra ensemble
```

CUDA is optional. LightGBM runs on CPU; XGBoost, CatBoost, and TCN can use an
NVIDIA GPU. Use `--cpu` to disable GPU execution.

## Run

EDA script:

```bash
uv run python eda_exam_rehearsal.py
```

Executed presentation notebook:

```bash
uv run jupyter lab eda_exam_rehearsal.ipynb
```

Fast real-data ensemble smoke test:

```bash
uv run --extra ensemble python parallel_ensemble.py --smoke
```

Larger four-fold experiment:

```bash
uv run --extra ensemble python parallel_ensemble.py \
  --folds 4 \
  --lookback-days 28 \
  --origin-stride 8 \
  --tcn-architecture two_stream
```

Tests:

```bash
uv run --extra ensemble pytest -q test_parallel_ensemble.py
```

## Limitations and next steps

- full multi-day backtest and final training were not completed;
- status semantics need a domain data dictionary;
- TCN errors remained highly correlated with boosting errors in preliminary runs;
- ensemble weights require more non-adjacent folds and stability analysis;
- inference packaging and final submission generation are not implemented in
  the validated pipeline;
- no causal conclusions are made from status correlations.

The next highest-value step is a non-adjacent multi-week backtest followed by
per-route and per-horizon error slices. Extra model complexity is retained only
if it improves cross-fitted validation rather than a single fold.
